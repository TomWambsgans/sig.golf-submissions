# Compact FORS+WOTS submission plan

This plan targets a valid sig.golf beta PR from `compact-sphincs-wip`. Its proof must close `SigGolf.Challenge.certificate` for the exact four submitted images; passing simulations or isolated Lean lemmas are not substitutes.

## Design decision

Freeze the proven instance for the first record: 160-bit digests, 24 FORS trees of height 8, 52 WOTS chains with target sum 194, six XMSS layers of heights `(11, 5, 5, 5, 4, 4)`, and lifetime `2^32`. Its signature and witness are 11,324 bytes. Redistributing the 34 height bits changes neither signature size nor the main verification hash count, yet forces edits through the specialized 127-bit proof and machine traces. A top layer of 12 exceeds both the keygen compression budget and the 128 KiB cache; the previous-VM keygen proof gives 1,007,616 of 1,048,576 allowed compressions; this result still needs transport to the final beta image. Change parameters only after a certified baseline and a measured score benefit.

Use the existing Lean SPHINCS security, correctness, and completeness theorems as the cryptographic core. The submitted program must implement *that exact scheme*, including byte serialization, retry order, and random-oracle queries. Keep `S = W = 11324`; `expand` copies the signature. Choose `C` from a proof of the accepting verifier path, not a single measured run. The working target is `C < 200000`, which would score below 2,264,800,000; keep the stated bound honest if the exact proof yields a larger value.

## Parallel work and interfaces

1. **Oracle and security bridge — agent A.** Keep the current HASH rule: lengths are multiples of 8 bytes. Define a bijection of oracle inputs swapping each relevant 60-byte tagged query with its four-zero-padded 64-byte query, and the 131,124-byte cache-MAC query with its 131,128-byte padded query. Prove the bijection and reuse the uniform-oracle simulation. Then prove the organizer's public-key commitment, attacker-replaceable cache, witness and signature final submissions, and event `won ∧ calls ≤ Q` reduce to the existing 127-bit argument with all keygen, signing, attacker, expansion, and verification calls charged. Deliver the game bridge conditional on exact program-refinement lemmas, then instantiate `submission.Secure` after those lemmas land; report any remaining quantitative loss explicitly.
2. **Images and VM service bridge — agent B.** Translate the existing four images to current beta services with appended, PC-preserving stubs. For each short HASH query, save the following 4-byte word, write zero, HASH the padded length, restore the word and registers, and jump back. The long MAC input ends at the cache tag, so restoration is mandatory. Prove each stub's entry/exit state relation, HASH input, compression cost, and unchanged original-PC fetches. Differentially test keygen, sign, expand, verify, invalid cache, and rejection. Deliver immutable beta image literals and exact instruction-site certificates; do not move the old code PCs. Then own the verifier six-layer induction, malformed-input gas proof, and honest accepting-cycle bound.
3. **Program refinement and bounds — agent C.** Reuse existing old-PC trace lemmas to complete the signer retry loop, 24-tree FORS opening, six WOTS/XMSS layers, and byte-exact signature output. Prove signer termination below `2^32` cycles for every input and oracle, including all retry branches. Prove the signer exponential compression moment; keygen and expand moments are already present but must be transported to the final beta images. Deliver signer `runWith` refinement and resource theorems, while agent B owns verifier refinement and its bounds.
4. **Integration — root.** Own the shared theorem signatures and dependencies so agents do not edit the same modules. Integrate only direct-Lean-checked patches, keep axiom guards, avoid source-root growth beyond 1,000 admitted entries and 16 MiB, assemble `SigGolf.Challenge.certificate`, then run the independent verifier on the exact PR tree. Push only the personal fork WIP branch while incomplete; open the normal PR against `beta` only when the full certificate builds.

## Gates

- **G1: exact images.** All four beta images pass static admission and differential runs. Every HASH call obeys 8-byte length/alignment, and the padded oracle query is proved equal to its abstract query under the bijection. Original-PC proofs still apply through the stub relation.
- **G2: cryptography.** The existing 127-bit theorem is reused without new unproved assumptions; the organizer game, public cache, 16-byte public-key commitment, and both forgery forms are covered under the *actual total* hash-call budget.
- **G3: programs.** Keygen, sign, expand, and verify are related to the high-level scheme for all inputs required by the rules. Honest executions preserve exact signature bytes. All four terminate for every input and oracle below `2^32` cycles.
- **G4: costs and completeness.** Prove success for every message except probability `2^-256`, each required exponential compression budget, and a certified `C` for every successful honest verification. Compute `S × C` from the final theorem.
- **G5: submission.** `Solution.lean` exports the exact certificate; full Lean build and independent verifier pass with only permitted axioms. Source-policy limits pass. Only then create the public PR.

Current state: the original 127-bit, correctness, and completeness theorems are Lean-checked, as are substantial old-VM traces. The beta submission has no certificate yet. The provisional `C = 1,000,000` in `claim.json` is a target, not a bound. The source is close to its 1,000-entry limit, so new lemmas should normally extend or consolidate existing modules.
