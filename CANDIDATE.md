# Compact SPHINCS candidate — work in progress

This branch contains a proposed submission in `submission/`. It is **not ready for a PR**: `SigGolf.Challenge.certificate` has not been proved. The values in `claim.json` are targets, not certified results: S = W = 11,324 bytes, C = 1,000,000 cycles, and S × C = 11,324,000,000. The cycle target is deliberately loose while the certificate is completed.

The current beta VM changed HASH lengths from bits to bytes, reversed the service selectors and HALT status, and added a witness-cycle charge. The previous-VM traces below do not yet certify the current beta submission. Lean now checks the four translated image literals and all 96 service-site fetch facts; the translated expand image also has an 8,503-cycle whole-program and zero-query monadic proof. The keygen, signer, and verifier execution bridges remain open. Current beta rejects 25 HASH sites with 60- or 131,124-byte inputs because it requires lengths divisible by eight bytes; no successful bridge for those sites is claimed.

## Lean-checked against the previous beta VM

- The exact keygen image returns the intended 16-byte public key and masked, authenticated cache for every secret key and random oracle. Its full trace, output bytes, 92,369,576-cycle termination, and keygen compression moment are proved.
- The exact expand image copies every signature byte into the witness. It terminates in 8,500 cycles, makes no hash calls, and meets its compression moment.
- The sign image loads and checks the masked cache. Its nonce and 24-tree FORS block has an exact trace and byte-for-byte agreement with the abstract scheme. The five lower WOTS layers have proved 52-chain endpoints and abstract leaf values, and their authentication paths are emitted byte-for-byte as the abstract `treePath`. The real forest-to-bottom-WOTS trace carries the digest and index through the handoff and subtree path to the first encoding HASH; its query and result match the abstract tweakable hash. When that digest decodes, the concrete padding and 52-digit checksum checks pass. The signer also has an exact 496-instruction digit-extraction trace and a proved retry prefix: n failed checksum attempts followed by a successful one reach chain signing in exactly 594n + 590 instructions, 601n + 597 cycles, and n + 1 HASH calls. Accepted digit bytes match the abstract encoding. From the accepted encoding PC, an exact trace copies the original 32-byte secret key, executes the first 576-bit secret HASH, and copies its truncated answer into the first WOTS buffer. The actual 72-byte HASH input matches the abstract `keygenHashInput` under an explicit signer context. A certified 55-instruction copy and prelude carry the required accepted-state facts to that HASH context. The forest, initial encoding HASH, accepted 52-digit decoder, and first bottom-layer secret HASH now compose through the required layer/tree/selected/parameter/seed context. Complete retries, WOTS signature-chain serialization, and full signer refinement remain open.
- The verify image has exact FORS and lower-layer WOTS traces and byte semantics. Upper-layer digit decoding, setup, 52-chain recovery, leaf HASH, and XMSS path recovery compose into a bounded trace at each of five relocated blocks; the recovered root equals the abstract root. The loaded witness places every XMSS path and WOTS chain byte at its verified address. A 43-cycle handoff preserves future witness bytes and puts the completed root into the next WOTS message. For the first upper layer, the exact 61-instruction, 68-cycle predecoder trace checks the signed counter, makes one HASH call, checks padding, and resets the digit sum, assuming an abstractly decodable HASH answer. The loaded top-layer counter is preserved through the layer-1 path and handoff. The exact layer-1 root reaches the top-layer message buffer. The global index is preserved through the upper-layer leaf, XMSS path, and handoff, with its next-layer value connected back to the original input. It yields the next tree and leaf controls, so the first top-layer HASH query is identified from the honest path-start state without ad hoc final-state premises. Composing all six layers and proving the claimed total cycle bound remain open. Commitment mismatches are proved to reject and terminate below the universal cycle limit.
- The inherited abstract SPHINCS security and completeness proofs build with only standard Lean axioms. A concrete altered-cache MAC first-hit bound and a finite lazy-oracle model for the full adaptive interaction are proved. The exact keygen cache has a joint law with a fresh dynamic MAC answer, and this law extends through the sampled secret key and organizer interaction. The stopped reference game has an exact lazy-oracle law for the within-budget winning event; its charged queries are bounded on that event. The numerical 128-to-127-bit margin for cache and seed bad events is proved. On budget-good full-certificate runs, the joint game proves the required bank contact without a support-wide query bound. The adaptive monitor's creation mass stays within Q even if its last signing call overshoots the true-cost budget. The weighted, independent proposal-word law then bounds the actual budgeted full-certificate event by Q times `fullCertificateTotalRate` plus an isolated exceptional probability. The exceptional event splits into cache-hit and proposal-prefix events, and its cache-hit probability has a Q-proportional bound for computations with a hard query cap. A pointwise reachable-state price cannot give the needed 127-bit rate; the proof retains the weighted law. The stopped signer retains the complete boundary trace, selected view, index, lazy-oracle cache, and remaining query budget. Its within-budget successful proposal-record law matches the original signer and is carried through one synthetic-length monitor update. The ghost remaining budget equals the initial budget minus actual boundary hash calls. The stopped and unbounded adaptive games have equal within-budget success-event mass, and the unbounded joint run projects onto the actual counted oracle. The counted cache-hit event with spent ≤ Q equals the stopped monitor event. Successful keygen initializes the joint cache and budget relation. A stopped-monitor potential argument bounds ghost cache-hit probability by Q times its rate across the signer-record wrapper and full adaptive game. A supported-run bridge now bounds the actual counted cache-hit event, within Q hash calls, by Q times the cache-exception rate without a multiplicative signer-work loss. The counted cache-hit bound now also averages over key generation. The weighted full-certificate bound now combines that cache rate with the structural rate and proposal-prefix exception. Coupling this abstract event to the concrete attacker and bytecode game remains open.

The active signer has a measured all-retries-last path of 4,113,270,860 cycles under the previous VM. Its 8,462,213 HASH calls would add 50,773,278 ordinary cycles under the beta service stubs, plus three for HALT, giving 4,164,044,141 cycles and 130,923,155 cycles of headroom under 2^32. This is an executable extrapolation for that path, not a proved universal bound. A separate scratch verifier gas prototype redirects 28 backward targets and is 29,104 bytes; its static interval and fetch facts have Lean checks, but its whole-program termination proof is still open.

The submission passes the independent source-admission check at 994 of 1000 allowed entries. Lean axiom guards on completed modules report only `propext`, `Classical.choice`, and `Quot.sound`.
