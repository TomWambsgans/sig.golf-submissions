# What does 128-bit security cost? (SECURITY_BITS 127 → 128, FORS+C submission)

Study of the record FORS+C submission (PR #35: S = 6404, C = 11,573, S × C = 74,113,492) under
`SECURITY_BITS = 128`: Pr[win] ≤ Q / 2^128 instead of Q / 2^127, everything else unchanged
(ROM with 256-bit answers, LIFETIME 2^32, FAILURE 2^-128, budgets, cache ≤ 128 KiB, 16-byte pk).

Implementation: `work/py-128` (ref.py = byte-exact spec, gen.py = the four RV64IM programs,
test.py = differential tests, PROGRAMS.md = program documentation). No Lean proofs, nothing pushed,
no existing source file modified (§9: one regenerated bytecode cache).

Hash work actually drops (788 compressions vs 803: 5 × 4 fewer chain steps, 5 × 1 more leaf
block); the cost is in instructions (7,583 vs 5,123): **a 129-bit value does not fit the
in-place 16-byte trick**, so every hash output that is re-hashed needs its 17th byte (or bit)
moved and cleaned.

## 2. Why 129-bit values, and what "the same proof shape" means

The 127-bit proof (sec-iter7, PROOF.md) works in units of 1/N with N = 2^128 and x = q/N:
every fresh query carries at most **two unit hazards** (a secret/hidden-input guess, and a fresh
output hitting a known canonical value). The crude route bounds the forgery probability by
`2x − x² + δx + q·r_cache + 2^-700` and closes for q ≥ q0 = 3·2^114; the refined route shows the
first-order coefficient is only 7/4 (a single chain contact is not a forgery; FORS secret guesses
are second order) and closes `(7/4 + δ)x + 2^-700 + x²/[2(1−x)²] + x(557x + 14q·r + 14·2^-700)/(1−x) ≤ 2x`
for q ≤ q0. The target 2x = q/2^127.

For 128 bits we need Pr ≤ q/2^128. Put **N := 2^129** and x := q/2^129: the target becomes
**2x** again. The whole argument transfers verbatim — both routes and all their closing
inequalities are statements about x only — provided the following invariants hold in the new
units (u = 2^-129):

* **(U1) hidden inputs**: every value an adversary would have to guess (unrevealed FORS secrets,
  WOTS chain values below the revealed position) is uniform on ≥ 129 bits given its view;
* **(U2) canonical outputs**: every value that a fresh output must hit to splice into an honest
  structure is compared on ≥ 129 bits;
* **(U3) encoding**: an equal WOTS encoding at a signed position has probability ≤ 2^-129 per query;
* **(U4) few-time prices**: the FTS constants (full-certificate excess δ = 11/65536, near price
  557, proposal rate 19/50, overhead 1537/1024, prefix exception 2^-700, r_cache) are unchanged
  when expressed in units of 2^-129;
* **(U5) negligible terms** (seed coupling, MAC, masks, exception rates) stay far below the slack;
* **(U6)** every cap "q ≤ 2^127" becomes "q ≤ 2^128" without changing a constant (for q > 2^128 the
  claim is trivial).

With 128-bit values the per-query hazards are 2 · 2^-128 = 4u, i.e. the old proof only gives 127
bits; **all six invariants are necessary** for the unchanged proof shape.

## 3. Chosen parameters and why

| parameter | 127-bit | 128-bit | reason |
|---|---|---|---|
| node values (FORS leaves/nodes/roots, roots hash M, OTS leaves, tree nodes, masks, randomizer) | 128 | **129** (`lo` 16 bytes + `b` = bit 0 of answer byte 16) | U1/U2 |
| WOTS chain values and chain secrets | 128 | **136** (whole answer byte 16) | U1/U2 need ≥ 129; 136 makes a chain step 11 cycles instead of 12 (no `andi`): −745 cycles for +188 bytes, a net win (§5) |
| FORS secrets | 128 (paired prf) | **129** | U1; two 129-bit secrets need 258 > 256 bits, so pairs give the lo parts and 4 extra prf answers per tree give the bits (516 prf queries per tree instead of 512) |
| WOTS secret derivation | 21 paired prf queries | **23-query stream**, secret i = bytes [17i, 17i+17) | 43 × 17 = 731 ≤ 23 × 32 |
| chains / code | 42 digits + 2 pinned bits (128 bits) | **43 base-8 digits = 129 answer bits**, no pins | U3; beats 42 digits + 3 pinned bits (T would drop to 179–180 under the sign budget: S −85, C ≈ +425, net ≈ +1.8 % worse) |
| target sum T | 184 | **195** | largest T with E[2^(K/2^17)] ≤ 2 (analytic 1.9943) |
| digest pin | 10 bits (u_14) | **11 bits** (174..184) | U4: every FTS price is multiplied by 2^-1 (pin) and by 2 (unit change) — the constants of the 127-bit proof are reproduced exactly |
| randomizer | rho_a = PRF(S, m, a), 128 bits, 3 compressions / trial | **rho = PRF(S, m) once, 129 bits; trial counter a in the digest tweak** (1 compression / trial) | U4: rho must have ≥ 129 bits so the adversary's cached digests stay at reuse weight 2^-(129-11) = 2^-118 (keeps the proposal overhead 1537/1024 with q ≤ 2^128); rho-once buys T+2 under the sign budget (3/trial: T = 193, 2/trial: 194) |
| public key | root (128 bits) | **root.lo, and the verifier requires root.b = 0** | the pk is 16 bytes: comparing 128 bits alone would be a 2u structural target. keygen grinds an 8-bit **root salt sigma** (p field of the root query; E[trials] = 2, failure 2^-256); sigma travels in the cache (MAC'd) and the signature |

| MAC tag | 256 | 256 | already ≫ 129 |

## 4. Formats (oracle blocks, signature, witness)

All oracle inputs are the exact blocks below (no relabeling needed any more); tweak
`enc(t, lay, tau, p, j)` as before, byte 1 = tag, one length per tag (domain separation).

| tag | block | blocks |
|---|---|---:|
| 1 chain step mu of chain i | `enc(1, lay, tau, (mu−1)\|i<<8, e) \| 0^31 \| v.hi \| v.lo` | 1 |
| 2 OTS leaf | `enc(2, lay, tau, 0, e) \| hi_0..hi_42 \| 0^21 \| lo_0..lo_42` (768 bytes; ends' lo parts last so the last step-7 answer spills outside) | 12 |
| 3 / 10 node | `enc(t, ·, ·, p, heap) \| L.b R.b 0^14 \| L.lo \| R.lo` (tw + 2 × 17 = 50 bytes fit; p = sigma only for the top root) | 1 |
| 4 encoding | `enc(4, lay, tau, 0, e) \| P \| M.lo \| LE64 M.b \| LE64 c` | 1 |
| 9 FORS leaf | `enc(9, k, idx, 0, j) \| P \| s.lo \| s.b \| 0^15` | 1 |
| 11 FORS roots | `enc(11, 0, idx, 0, 0) \| b_0..b_13 0^2 \| lo_0..lo_13` | 4 |
| 12 digest | `enc(12,0,0,0,0)[0:8] \| r \| rho.lo \| m`, r = rho.b \| a<<32 | 1 |
| 0 / 8 / 13 prf | `enc \| P \| S` | 1 |
| 7 randomizer | `enc(7,0,0,0,0) \| P \| S \| m` | 2 |
| 14 MAC | `enc(14,…) \| P \| S \| region` (region = 4094 masked lo, 4094 masked b bytes, 0^2, LE64 sigma) | 1089 |

**Signature bytes vs verify cycles.** S counts bytes, the witness only ⌈W/256⌉ cycles, and expand
is free. So the signature is bit-packed, the witness is not, and verify never unpacks:

* signature (6720) = `[all 404 lo parts, byte aligned (6464)] [215 chain hi bytes] [41-byte bit
  field: rho.b, a (20), sigma (8), c_0..c_4 (22 each), 154 FORS b bits, 34 path b bits, 1 spare
  bit = 0]` — within 1 byte of the information-theoretic packing (53,759 bits);
* witness (6900) = the same 6679 core bytes + the small fields unpacked into aligned words / one
  byte per b bit. expand = copy + unpack; it **rejects a set spare bit**, so signature ↔ witness is
  a bijection (otherwise flipping the spare bit would be a trivial strong forgery).

Putting the lo parts first and grouping the 1-bit / 8-bit remainders makes packing free for
verify: every 16-byte value is 8-aligned in the witness (ld/sd), every b / hi is one `lbu`.
Packing 8 values into 129 bytes (plain bitstream) would save nothing further in S (the current
layout is already optimal to the bit) and would force unaligned multi-shift loads in verify.

## 5. Engineering: the verifier

Same architecture as the record (loop-free, two-track Merkle folds, JALR pair dispatch tables,
value-last chain blocks, constant registers); PROGRAMS.md has the block-by-block description.

* **Why a 129-bit value is expensive in place.** HASH writes 32 bytes at an 8-aligned address and
  reads an 8-aligned block, so the part of an answer that lands inside the next 64-byte input is
  0, 8, 16, 24 or 32 bytes. 128 bits (the old design) or 192 bits are free; anything in between
  needs the 17th byte copied and, for 129 bits, cleaned (`lbu; andi; sb`), or the whole byte kept
  (136-bit chain values: `lbu; sb`). No single RV64 instruction loads a clean bit, so 2 extra
  instructions per chain step and 3 + 2 per Merkle fold are the floor for this approach.
* **Chain step** (11 = 3 + 8): `sb MU, 4(a0); ecall; lbu T, 64(a0); sb T, 47(a0)`. Step 7 writes
  the end into the leaf slot and moves its byte into the hi array (12). Chain head
  `ld; ld; lbu hi; sb P_i/x0 (i ≤ 6) or addi+sb; addi a2; jalr`, entries `sd; sd; sb; jal`
  (16 bytes). Chain i costs 11(7 − x_i) + 11 + [i ≥ 7] (x_i = 7: one cycle less).
* **Two-track fold** (22 = 14 + 8): V.b from V's answer byte 16 (`lbu NB+48+16t; andi; sb
  NB+16+t` — for t = 0 it is read out of the sibling slot before the copy), sibling lo (4),
  sibling b (`lbu; sb`), heap index (2), branch point (2), `addi a2; ecall`.
* **Digit 42 / bits 63, 127**: the single-chain tables for digits 20 and 41 have 16 entries indexed
  by bits 60..63 (so the unused bits 63/127 need no mask); the SWAR sum uses M1 without its top
  group for the shifted terms (kept in the dead idx register). Encoding check 23 instructions.
* FORS needs three tracked regions (branch range), costing one extra merge cycle.

Alternatives evaluated (verify cycles / signature bytes, all at the sign budget):

| alternative | effect | verdict |
|---|---|---|
| 129-bit chain values | S 6532, C ≈ 14,659 → S × C ≈ 95.8M | 136-bit better by 2.4 % |
| 192-bit chain values (in-place, 9-cycle steps) | S ≈ 8225, C ≈ 12,400 → ≈ 102M | worse |
| 42 digits + 3 pinned bits (T ≤ 180) | S 6635, C ≈ 14,340 → ≈ 95.1M | worse |
| 44 / 45 digits (T 198 / 202) | more steps than 43 digits at the budget | worse |
| digest 3 compressions/trial (old structure) | T = 193: C +110, S −2 | +0.8 % |
| pin 10 + a sharper tail bound for δ instead of pin 11 | T = 195 as well (the 11th pin costs 0.55 % of the moment, still ≤ 2) | no gain |
| w = 16 (33 digits) | S −12 %, but ≈ +3,300 cycles | worse |
| witness-resident node/chain blocks (hash from the witness) | the 16-byte answer spill clobbers the pre-placed sibling for left children | not usable |
| 32-byte dispatch entries / store-in-head | x = 7 paths get more expensive (the max counts them) | worse |

## 6. Security argument (pen and paper)

Notation: N = 2^129, x = q/N, unit u = 1/N. Claim: every adversary whose experiment makes at most
q oracle calls wins (weak witness or strong signature unforgeability) with probability ≤ 2x =
q/2^128. For q ≥ 2^128 there is nothing to prove.

### 6.1 Reduction to the ideal scheme (unchanged structure)

1. **Seed coupling.** Every derivation (WOTS stream, FORS pairs and extras, masks, randomizer, MAC)
   contains the full 32-byte S; until a query names S the derived values are independent uniform
   strings. Loss ≤ q'/2^256. Derived secrets are disjoint slices of independent answers (a pair
   half + one bit of an extra answer; a 17-byte slice of the stream), hence independent and
   uniform on 129 / 136 bits: **(U1) holds**, including conditional entropy given revealed
   neighbours (no bit is shared).
2. **Untrusted caches.** A cache whose region differs from keygen's passes the MAC check only if
   H(tw_mac | P | S | region') equals the stored 256-bit tag: ≤ 2^-256 per signing request.
   Masks are 129-bit one-time pads, so the public cache reveals nothing about node values.
3. **Deterministic signer**: repeated requests are answered identically (rho = PRF(S, m); the
   first admissible a); distinct messages get independent rho.

### 6.2 Per-query hazards (units of 2^-129)

| query class | hazard(s) | 127-bit design (units of 2^-128) | 128-bit design (units of 2^-129) |
|---|---|---|---|
| WOTS chain step | guess hidden v (136-bit) + hit next value (136-bit) | 1 + 1 | 2^-7 + 2^-7 |
| FORS leaf (tag 9) | guess s (129-bit) + hit leaf (129-bit) | 1 + 1 | 1 + 1 |
| FORS node, roots hash, OTS leaf, tree node | structural hit (129-bit canonical value) | 1 | 1 |
| top root (any sigma) | output.lo = pk and output.b = 0 | 1 | 1 |
| encoding (tag 4) | equal digit vector at a signed position: 129 fixed answer bits | 1 (126 + 2 pins) | 1 (43 × 3) |
| digest (tag 12) | FTS certificate price: 2^-34 · 2^-pin · Σ cov^14 over idx | 2^-10 · 2^-34 · 2^128 · … | 2^-11 · 2^-34 · 2^129 · … = **identical** |
| prf / mask / MAC / randomizer | name S (32 bytes) | 2^-256 per query | 2^-256 per query |

So every query carries ≤ 2 units (**U2, U3**), exactly as in the 127-bit proof. Single-target
structure is unchanged: every position (tag, layer/tree, tau/idx, heap index or (i, mu), e) has
one canonical value; the root position is the only one whose target is shared by all salts
sigma, and there the target (pk, b = 0) is a single 129-bit condition.

### 6.3 Few-time part (U4)

The certificate price of a digest query is P(index) · P(admissible) · Π_k (covered fraction of
tree k) = 2^-34 · 2^-11 · Π_k c_k/1024. In units of 2^-129 this is 2^-56 Σ_idx c_idx^14 — the same
function of the signature counts as the 127-bit proof's "price" 2^-56 Σ c^14 in units of 2^-128
(there the pin was 10 bits). Likewise the near price (13 trees covered, one omitted) 557/14 per
omitted tree, the full-certificate excess δ = 11/2^16, the proposal-word model (length
q_s · 1537/1024 + 2^23, rate 19/50, prefix exception 2^-700) and the digest cache-exception
thresholds: the arrival rate becomes 2^-45 per query, so with q ≤ 2^128 the cached multiplicity
per index is ≤ 2^83 as before; the signer's digest can be pre-queried only by guessing rho
(129 bits), reuse weight 2^-129 · 2^11 = 2^-118 as before, hence the overhead 1537/1024 and the
rate 19/50 are unchanged. The FORS secret guesses in the forced near games are over 129-bit
secrets, i.e. 1/(N − q) per query, the same formula in the new N. **All FTS closers are therefore
reused numerically** (after replacing admissibility 2^-10 by 2^-11 and 2^128 by 2^129 in the same
products).

Sanity check of the magnitudes (Poisson model, 14 trees × 2^10, 11 pinned bits): the average
probability that one digest query yields a full FORS forgery is 2^-134.27 at the true index load
q_s/2^34 = 1/4 (0.026 units) and 2^-131.37 at the proof's padded proposal rate 0.38 (0.19 units,
the lemma "mean ≤ 1/5"); the near-certificate mass (13 of 14 trees covered) is ≈ 542 units ≤ 557.

(Without the 11th pinned bit every FTS price doubles in the new units: near price 1114, and the
excess over one unit grows to ≈ 2^-11.5 (if it simply doubled) or ≈ 2^-10.2 (the proof's
second-moment technique applied to the doubled price). The refined route then closes only up to
q ≈ 2^116.9 while the crude route starts at q ≈ 2^117.5..2^118.8: a gap. A sharper tail estimate of
the excess — its true value is ≈ 2^-30 (it needs an index with ≥ 15 of the ≈ 0.38 · 2^34
proposals; the proof's variance bound is loose by 20 bits) — would close it
without the pin; the pin is simpler and costs no T.)

### 6.4 Closing arithmetic (identical inequalities in x)

* q ≥ q0 := 3 · 2^115 (x ≥ 12 · 2^-16 > δ = 11 · 2^-16): crude route
  `2x − x² + δx + q·r_cache + 2^-700 ≤ 2x` ⟸ x(x − δ) ≥ x · 2^-16 = q · 2^-145 ≥ q · 2^-153 + 2^-700.
* 1 ≤ q ≤ q0: refined route, left side at q0 ≈ (1.75 + 0.0002 + 0.0001 + 557 · 1.83·10^-4) x ≈ 1.852 x
  ≤ 2x (the same 0.15x slack as the 127-bit proof). The primitive coefficient 7/4 now has extra
  room: the chain-related first-order term (two-edge completion, 3/2 per prefix query at 128-bit
  chains) is 3/2 · 2^-7 with 136-bit chains, and the marker-and-contact terms (unit-neighbour count
  43 · 42 = 1806) shrink by 2^7 as well.
* Seed coupling q'/2^256, MAC failures ≤ 2^32 · 2^-256 and the proposal exception fit in the
  one-query slack as before.

**Per-term budget at the worst point q = q0 (in units of x = q/2^129; target 2):** OTS/structural/
encoding primitives ≤ 1.75 (union bound over the four query classes, each ≤ 1 unit except chain
queries at 2^-6), FTS full-certificate excess 0.00017, two FORS guesses 0.0001, near certificate
× guess 0.102, cache exceptions 2^-24, prefix exception 2^-700 (absolute), seed coupling and MAC
< 2^-126: **total ≈ 1.852**.
For q ≥ q0 the crude route: 2 − x + δ + 2^-24 ≤ 2.

### 6.5 Completeness and budgets (FAILURE = 2^-128)

keygen fails only if all 256 salts give root.b = 1: 2^-256. Per message: digest search
(1 − 2^-11)^(2^20) ≤ e^-512; each of the 5 counter searches (1 − 2^-11.612)^(2^22) ≤ e^-1340.
Union over all 2^256 messages: ≤ 2^256 (e^-512 + 5e^-1340) + 2^-256 < 2^-250. Budgets: sign
E[2^(K/2^17)] = 1.9943 (deterministic 112,690 compressions: MAC 1089, rho 2, FORS 14 · 2563 + 4,
layer trees 224 · 336 + 220, layer 0 23 + T + 11; geometric digest p = 2^-11 and 5 counter searches
alpha = 2^-11.612, 1 compression per trial; empirical 1.9933 over 400 signings); keygen 695,359
compressions + salt trials: 1.584; expand hashes nothing. Worst-case sign 838.8M cycles < 2^32.

### 6.6 The variant with 128-bit FORS internal nodes (row 2 of §1)

FORS nodes above the leaves and the 14 FORS roots are 128-bit (leaves and secrets stay 129-bit:
a FORS leaf query already carries guess + hit). Crude route: a FORS node query carries one 2-unit
hit, still ≤ 2 units — fine. Refined route: a FORS structural hit covers one tree for one
subtree, so it is *not* a forgery by itself; it must be moved out of the first-order primitive
union (where it would cost 2 > 7/4) into the forced FTS games next to the secret guess
(near certificate × hit = 557x · 2x, pairs of FORS events (3x)²/2). With the proof's current δ
bound the two routes then leave a gap at q ≈ 2^116.3..2^116.5; a sharper tail bound for δ (or a
12th pinned bit, T = 194, C +55) closes it. This is a genuinely new proof component, hence a
separate row (saves 658 cycles and 15 bytes: −4.9 %).

## 7. PORS+FP under the same change (estimate, not implemented)

The same invariants apply: 129-bit PORS secrets / octopus nodes (+5 per fold, ≤ 120 folds, +6 per
merge), +1 pinned digest bit, 136-bit chains, 43 digits; its heavier signer (PORS tree 40,959
compressions) allows T ≈ 193. Estimate: C ≈ 14,230 (11,907 + 600 octopus folds + 84 merges + 30
leaves + ≈ 1,600 hypertree layers + 7), S ≈ 6,420 (+215 hi, +80 43rd chain, +25 bit field):
S × C ≈ 91.4M, **+26 % vs 72,632,700** (uncertainty ±2 %). PORS stays ≈ 2 % ahead of FORS in
the 128-bit world; the 128-bit-FORS-internal trick applies to its octopus nodes too (≈ −4 %).

## 8. What a full Lean proof would need to change (brief)

* **Scheme / statement**: the new byte formats (no relabeling f, so the program bridge gets
  simpler), 129-bit node values and 136-bit chain values as byte strings with the `b`/`hi`
  convention, the 43-digit code with T = 195, pin 11, the rho-once digest loop with counter a,
  the prf stream and FORS extras, the root salt in keygen and the root condition in verify, the
  bit-packed signature with the spare-bit check in expand; SECURITY_BITS 128.
* **Security proof**: N = 2^128 → 2^129 wherever it is the value-space size (uniform tables of the
  hidden coordinates are now over 129-/136-bit values; the two-unit potential), caps q ≤ 2^127 →
  2^128, q0 = 3·2^115; `Ots/Code.lean` (decoder, validity, injectivity, incomparability, unit
  neighbours 1806, default word) and the chain tweak arithmetic ((mu−1) | i<<8); the FTS closers
  with admissibility 2^-11 (products unchanged); the new randomizer structure in the digest-loop
  modules (DigestLoopRecord, SignerDigestSource, completeness Digest.lean — which becomes simpler:
  no repeated randomizers); a new structural-match target for the salted root; seed coupling for
  the stream / extras derivations; MAC over the new region. The closing arithmetic files are
  re-run with the same constants in x. For the §6.6 variant additionally: FORS structural matches
  in the forced games and a sharper δ.
* **Completeness**: code count (≥ 2^117.39 of 2^129 answers decode), salt failure, digest loop.
* **RISC-V refinement**: new program images; the verify cycle bound becomes "13,887 −
  #(digits = 7)" (or pad the x = 7 entries), new block shapes (b extraction, byte copies, 16-entry
  single tables, salt, root bit).

## 9. Uncertainties and caveats

* The security argument transports the structure of the 127-bit Lean proof; it was checked on
  paper term by term (§6), not re-proved. The riskiest spots are constants derived inside the FTS
  modules that implicitly use 2^128 (cache-exception rate, the 2^72 threshold): they are tiny
  compared with the 0.15x slack, but must be re-derived. The pin-11 / rho-129 argument makes every
  FTS product identical, which is why we expect no surprise there.
* The sign budget is tight (analytic 1.9943); it has the same kind of margin as the record
  (1.9913). T = 196 would give 2.03.
* Cycle counts are exact for the emulator (and for the organizer VM semantics it mirrors); the
  bound "13,887 − n7" is checked on honest, forced-encoding and table-cover runs.
* The PORS figure (§7) is an estimate.
* Housekeeping: while measuring the old per-phase breakdown I ran Python in py-opt8, which
  rewrote its `__pycache__` bytecode (regenerated; no source file touched).
